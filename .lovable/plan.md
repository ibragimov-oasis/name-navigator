# План: Мастер подбора имени + синхронизация каталога

## Этап 1. Мастер (src/pages/NameWizard.tsx, src/lib/nameHarmony.ts)

1. **Учёт имени матери** — `calculateHarmony(first, father, surname, gender, opts?: { motherName?, siblings? })`. Старая сигнатура сохраняется (необязательный параметр). Итог = отец (звучание ФИО с отчеством) 45% + мать (созвучие с именем ребёнка: переход, ритм, отсутствие повтора первой буквы/окончания) 35% + фамилия (переход фамилия→имя, длина) 20%. Если матери нет — её вес перераспределяется пропорционально. В `details` добавить `mother`, `father`, `surname`.
2. **Глобальное избранное** — заменить локальный `useState<Set>` на `useFavorites()` из `src/lib/favorites.tsx` (`isFavorite`/`toggleFavorite(id)`). Имена появятся на /favorites и сохранятся после перезагрузки.
3. **Озвучка ФИО** — кнопка на `Volume2`: `speechSynthesis` читает полное ФИО (`fullName`), язык ru-RU, остановка предыдущей речи, `aria-label`, скрытие кнопки если API недоступен.
4. **Живое обновление** — `useEffect` слушает `names-updated` и пересчитывает список (счётчик версии в зависимостях `useMemo`); при монтировании вызывать `loadEnrichedNames()`.
5. **Кликабельная карточка** — диалог деталей (значение, происхождение, история, известные носители, гармония по пунктам, кнопки озвучки/избранного/«Открыть страницу имени»). Новый компонент `src/components/wizard/WizardNameDetailDialog.tsx`.
6. **Братья и сёстры** — новый шаг с вводом до 5 имён старших детей. Оценка созвучия: общее окончание (2–3 буквы), общий корень/первая буква, близкое число слогов; штраф за полное совпадение. Входит в сортировку бонусом и показывается бейджем «Пара к …».
7. **Бейдж ЗАГС РТ** — для имён культур таджикская/персидская: ленивая загрузка реестра через `fetchRegistry()` + `checkTajikNameLegality`; бейджи «В реестре РТ» / «Похоже на …» / «Нет в реестре».
8. **Дополнительно** — «Показать ещё» вместо жёсткого `slice(0, 20)` (шаг 20).

Тест: `src/test/nameHarmony.test.ts` — веса 45/35/20, перераспределение без матери, бонус за созвучие с братом/сестрой.

## Этап 2. Синхронизация каталога в репозиторий

1. `scripts/sync-enriched-to-repo.ts` (запуск через `bun`): постранично (по 1000) читает `names_enriched` со `status='published'`, исключает имена, уже есть в статических батчах `src/data/names/**` (ключ: имя в нижнем регистре + пол + культура), дедуплицирует, сортирует, пишет `public/data/catalog-enriched.json` (`{ generatedAt, count, names[] }`). Ключи из `.env` (`SUPABASE_URL`/ключ). В package.json: `"names:dump": "bun scripts/sync-enriched-to-repo.ts"`.
2. `src/lib/namesStore.ts`: сначала загружать `catalog-enriched.json`, затем из БД — только записи новее `generatedAt` (дельта).
3. Edge Function `enrich-names`: генерировать в репозитории `supabase/functions/enrich-names/static-names.json` (список ключей статики, создаётся тем же скриптом), фильтровать результат ИИ по нему и передавать в промпт пример существующих имён выбранной культуры; задеплоить заново.
