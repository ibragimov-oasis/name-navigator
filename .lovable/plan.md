# Автоматический парсинг и обогащение имён

## Цель

Сайт сам пополняет базу имён (значения, происхождение, история, атрибуты) — без ручного ввода. Запуск по расписанию (например, раз в час) + кнопка «Запустить сейчас» в админке.

## Архитектура

```text
[pg_cron каждый час]
        │
        ▼
[edge: enrich-names]  ──►  Gemini API (1 batch = 5–10 имён)
        │                   ▲
        ▼                   │
[Supabase: names_enriched]  └── источники-сидеры:
        │                       • открытые списки (Behind the Name, Quran.com)
        ▼                       • Firecrawl scrape (опционально)
[фронт: getChildNames() мерджит статические батчи + БД]
```

## Что добавляем

### 1. Таблицы Supabase
- `names_enriched` — имена, сгенерированные/спарсенные автоматически
  поля: `name`, `gender`, `origin`, `culture`, `religion`, `meaning`, `attributes[]`, `history`, `popularity`, `source` (gemini/behindthename/quran), `verified` (bool), `created_at`
- `enrich_queue` — очередь «сидов» для обработки
  поля: `seed` (буква/тема/культура), `status` (pending/done/failed), `attempts`, `last_error`

### 2. Edge-функция `enrich-names`
- Берёт N pending-сидов из `enrich_queue`
- Для каждого зовёт Gemini с жёстким JSON-schema промптом («дай 10 имён по теме X в формате…»)
- Дедуп по `lower(name) + gender` против `child_names` (статика) и `names_enriched`
- Кладёт результат в `names_enriched`, помечает сид как `done`
- Лимит токенов: пакетами по 10 имён, не больше 50 имён за запуск

### 3. Cron
- `pg_cron + pg_net` → вызывает `enrich-names` раз в час (настраиваемо)

### 4. Сидер (одноразово)
- Заливаем в `enrich_queue` ~200 стартовых сидов: «арабские мужские на А», «турецкие женские», «персидские суфийские», «татарские редкие» и т.д.

### 5. Фронт
- `namesStore.ts`: при загрузке подтягивает `names_enriched` (where verified=true ИЛИ автоприём) и мерджит со статикой
- Новая страница `/admin/enrich`:
  • статус очереди (pending/done/failed)
  • кнопка «Запустить сейчас» (вызов edge-функции)
  • таблица последних 50 добавленных имён с кнопками ✓ verify / ✗ delete
  • форма «добавить сид вручную»

### 6. Опционально — Firecrawl
Если хотите парсить реальные сайты (Behind the Name, Quran.com), подключаем Firecrawl-коннектор и добавляем второй режим в `enrich-names`: сначала scrape, потом Gemini структурирует HTML → JSON. Без Firecrawl всё работает только через Gemini (он сам знает имена).

## Что НЕ делаем
- Не удаляем существующие статические батчи (`batch_xxx.ts`) — память: «NEVER delete existing code».
- Не льём в БД секреты, не показываем service_role на фронте.
- Не запускаем без RLS: `names_enriched` — публичный SELECT, INSERT/UPDATE только service_role (через edge-функцию).

## Вопросы перед стартом

1. **Источник имён**: только Gemini (быстро, бесплатно в рамках Lovable AI), или подключить Firecrawl для парсинга Behind the Name / Quran.com (точнее, но платно)?
2. **Авто-публикация**: новые имена сразу видны на сайте, или сначала ваша модерация через `/admin/enrich`?
3. **Частота cron**: раз в час / раз в сутки / только по кнопке?
4. **Фокус сидов**: продолжаем 90% ислам (как в core-памяти), или равномерно по всем культурам?

После ответов сразу создаю миграцию + edge-функцию + админ-страницу.
