## Проблема

`enrich_runs`: 118 запусков, все `error: gemini 429`. `names_enriched`: 0 строк. `llm_quota_usage`: пусто.

Причины в `supabase/functions/enrich-names/index.ts`:

1. **Несуществующие model id** в списке `MODELS` (`gemini-3.1-flash-lite`, `gemini-2.5-pro`→`gemini-2.5-flash` и т.п.) — на самом деле в `generativelanguage` API таких имён нет, они маппятся на `gemini-2.5-flash-lite` с дневным лимитом 20 → мгновенный 429.
2. **Квота инкрементится после вызова**: если вызов падает 429, `bumpQuota` не выполняется → `pickModel` всегда возвращает первую модель → бесконечный цикл по одной и той же исчерпанной модели.
3. **Нет обработки 429**: 429 не помечает модель как «выбран дневной лимит», просто валит run.
4. **Gemma-модели** (`gemma-3-27b-it`, `gemma-3-12b-it`) вызываются через тот же эндпоинт, но фактически не отдаются ключом → тоже 429/403.
5. Cron каждые 15 минут только плодит ошибки.

## План фикса

### 1. Переписать enrich-names

- **Реальный список моделей** (проверенные имена API):
  - `gemini-2.0-flash-lite` (RPD 200)
  - `gemini-2.0-flash` (RPD 200)
  - `gemini-2.5-flash-lite` (RPD 1000)
  - `gemini-2.5-flash` (RPD 250)
  - `gemma-3-27b-it` / `gemma-3-12b-it` / `gemma-3-4b-it` (RPD 14400 — через тот же `:generateContent`)
  - Сортировка: сначала самые «дешёвые/многоквотные» (Gemma → 2.5-flash-lite → 2.0-flash-lite → 2.0-flash → 2.5-flash).
- **Bump квоты ДО вызова** (резерв слота), а на ошибку 429/403 — пометка модели как `exhausted_today` отдельной записью в `llm_quota_usage` (ставим `requests = rpd`, чтобы `pickModel` её сразу пропускал) и ретрай со следующей моделью в том же запуске (до 3 моделей за run).
- **Фолбэк парсера JSON**: если `responseMimeType: application/json` не сработал (Gemma не всегда поддерживает) — выдрать JSON-массив регуляркой из текста.
- **Несколько культур за запуск** (3 батча по 10 имён, разные культуры) — чтобы один cron-тик давал ~30 имён.
- **Логирование** в `enrich_runs.errors` причины (429/parse/empty) для дальнейшей диагностики.
